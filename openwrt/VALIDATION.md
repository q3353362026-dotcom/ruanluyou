## UDP 下行采集修复（0.5.12-r2）

- 旧版 AF_PACKET 使用 ETH_P_IP，只收到 LAN 接口的入站包，遗漏发往客户机的下行包；
  初始握手可见，但 BankBroker 无法取得下行验证证据，因而没有 bank_bound。
- 改为 ETH_P_ALL 订阅收发包，并按 sockaddr_ll 的 EtherType 筛选 IPv4。
  保留原有客户机、UDP、长度校验与 bank 验证条件。
- 网络命名空间回归测试新增真实 UDP 往返，断言日志同时包含 up/down。
  旧版测试仅得到 up 并失败；修复后通过。Linux CTest 21 项通过，Python 3.14 参考测试跳过。
- TR3000 旧版实机对照：电脑成功收到路由器 DNS 回复，采集日志仍只有 1 个上行包。
- 升级至 0.5.12-r2 后，完全相同的实机测试记录 1 个上行包与 1 个下行包，服务正常运行并保留开机启动。
  真实游戏会话仍需重新连接验证；此次修复没有放宽 bank 绑定验证。

  同时验证省略时长、手动停止、1 秒定时结束、SIGTERM 清理。
- Linux CTest 21 项通过、1 项 Python 3.14 参考测试跳过；前端 JavaScript 语法检查通过。

- TR3000 已安装 r3，实机 API 验证 `seconds=0` 持续运行且可手动停止；浏览器确认时长默认 0
  与“不限时”提示可见。测试采集已停止，服务保持运行。
