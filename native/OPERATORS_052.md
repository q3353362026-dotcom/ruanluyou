# 干员头像与名称 · 0.5.2

雷达以已解析的 `attributes.heroId` 匹配原版干员表，在现有圆圈中裁切显示头像。头像保持正向，只有朝向箭头旋转；队伍颜色保留在外圈，倒地十字、暂存虚线和透明度保持有效。默认圆半径由 9 调整为 14 像素，让头像更易辨认，仍受原有大小滑块控制。

地图标签显示玩家名与干员名，列表增加圆形头像与干员名称，详情增加干员字段，搜索支持玩家名、干员名、队伍和槽位。没有识别到干员时显示“未知干员”；没有对应图片或图片加载失败时保留原来的圆点，不隐藏人物、不猜测头像。

名称来自仓库原版 `runtime/ErCore/item_names_cn.json` 的 `operators.Name`，保留原版 `liveview.HERO_NAME_OVERRIDE` 对佐娅、旅人的覆盖。生成结果包含 40 个名称、18 张有确切名称映射的本地 PNG；没有把未绑定的头像强行分配给其他角色。数值 ID 不用位运算截断，可正确表示 `88000000027` 这样的 HeroId。

资源为 `native/webui/radar/operators.json` 与 `native/webui/radar/portraits/`，可以使用 `native/tools/generate_operator_assets.py` 从原版资源重新生成。图片直接复制，生成时核对 SHA-256；不需要外部图片服务，也不需要 Python 参与运行。

客户端每种干员只加载一次头像；地图和列表共同复用已解码图片，列表使用 canvas，避免高频重建 DOM 触发重复图片请求。服务端只注册目录表中明确列出的数字文件名，按 `image/png` 返回。启动检查和便携包包含这些资源。

验证覆盖实际页面脚本的头像加载、地图名称、头像保持正向、缓存复用和图片失败退回圆点，以及 HTTP 对全部 18 张图片的 MIME/PNG/字节一致性与路径边界。沿用现有坐标保留与生命状态回归测试。本次未启动真实采集。

重新启动项目根目录的 `start.cmd` / `start-admin.cmd`，再刷新雷达。旧服务会保留启动时加载的静态资源，仅刷新浏览器不能更新它。
