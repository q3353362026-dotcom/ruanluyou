分析日期：2026-10-18。SDK 附件：`1.101.37117.36.5-SDK+基址-2026-09-23-粥.zip`。只读取文本，没有执行附件代码；解压文本和回放产物保存在开发目录 `native/build/sdk-review-20260923/`，不进入运行包。

结论：这份 SDK 有助于核对类/字段和后续定位，不能单独补全 0x10 网络格式，也不能保证当前客户端与该 SDK 完全同版。本次实现依据已有网络位流解析器、原版实际停止行为和日志差分，不把内存布局当作 wire format。

## “未通过”的原因

固定快照来自用户运行中的 0.3.3 日志 `web-1792307252722-fb905900.jsonl`，时间范围 UTC+8 15:07:32.725–15:15:08.604，截取 89,380,820 字节的完整行，共 100,711 条事件、21,422 个 UDP 明文包。没有停止采集或修改原日志。

快照 SHA-256：`7a471bdd999aabb33e6d8075218946b215127fcecfa1be0661116bad281f0d69`。

1,319 个拒绝样本中，1,318 个带 `decoder_error_during_sample`，另 1 个为 `out_of_order`；没有坐标越界或超速标记。旧实现把整条流的错误增量传播给所有槽位，使其他通道解析错误也重置人物连续性。

361 条旧诊断中，245 条为 0x10 对象未支持，31 条为 h21 后存在其他属性。原版遇 0x10 会先保留当前 item 中已读字段，再停止整帧后续读取；旧 C++ 直接抛异常，连此前坐标一起丢弃。非可靠 bunch 抛异常还会清空全流重组缓存。

## 已落地的调整

- 只在已确认移动通道保留已知前缀，标记帧/属性块是否完整与停止原因；未知对象后不继续猜读。
- 单通道错误局部处理，不清空其他通道重组状态；人物只累计相关错误，未知边界的包级错误仍保守影响下行流。
- 部分解析提示单独保存为 `player_decode_warning`；WebUI 显示覆盖标记及中文校验原因，离线输出增加 `decoder-warnings.jsonl`。
- 握手、世界边界、时间顺序、连续样本门槛和配置的速度检查保持生效，部分解析也不跳过这些检查。

276 条未支持提示仍然存在，只是不再冒充全部坐标失败。0.3.4 输出中有 651 条明确标记为部分解析的坐标，19,840 条来自完整移动块。

原有 19,833 条坐标按 flow、epoch、channel、slot、源包、时间和数值逐条保留，不改变坐标/朝向。新增 658 条（651 条前缀、7 条恢复的完整块）全部与原 Python 的同槽位、时间 ±1 ms、坐标容差 1e-6 及朝向匹配。

原 Python 共输出 20,509 条；新版 20,491 条中 20,490 条匹配，1 条差异原已存在，没有在本轮改写。不同重组和状态维护策略仍有差异，原版也不是独立游戏真值，因此以上数据不能解释成真实坐标准确率。

剩余 83 条错误主要是位流截断、缺失压缩上下文、packed integer/FString/FName 边界异常、未知属性等，仍须进一步确认版本、丢包或解析覆盖原因。0x10 对象本身依然未解码；完整支持需要对应序列化实现或等价的协议证据。

验证包括 12 项 CTest、358 组底层原版差分向量、部分解析与通道隔离回归、模拟 WinDivert 到 WebUI 的提示展示及相同日志回放。未新增实机抓包；浏览器视觉验收受既有本机页面访问权限限制，WebUI 数据通过本地 HTTP 测试验证。
