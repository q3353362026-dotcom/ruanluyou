# WebUI 与局域网设备发现

原生 C++ HTTP 服务、Windows 网卡/邻居发现和共享采集使用同一个 `radaer-native.exe`。
页面是本地 HTML/CSS/JavaScript，无需 Node、Python Web 服务或 CDN。

0.5.0 起，控制台点击「打开雷达」进入独立 `/radar` 页面，与控制台共用采集、解析和日志。雷达采用本地 Leaflet 与 Canvas；原版地图瓦片从 `game.gtimg.cn` 加载，没有网络时可选「坐标网格 · 离线」。新数据字段、刷新口径及验证记录见 [RADAR_050.md](RADAR_050.md)。下文带版本号的内容是对应版本的历史记录，当前页面行为以 0.5.0 说明为准。

## 启动

在项目根目录执行；需要采集时请使用管理员 PowerShell：

```powershell
native/tools/start-webui.ps1
```

启动时选择一个网卡地址，绑定成功后自动打开默认浏览器；本机与其他设备均使用该地址。仅本机模式使用 `http://127.0.0.1:8765`。
保留终端窗口，Ctrl+C 正常停止服务和当前采集；只关闭网页不会停止原生服务/正在运行的采集。
查看网卡和扫描设备通常不需要管理员，WinDivert 采集需要管理员。

```powershell
native/tools/start-webui.ps1 -NoBrowser -Port 8766 -OutputDirectory C:/captures/radaer
native/tools/run-native.ps1 webui --port 8765
```

0.5.8 启动脚本要求选择单个网卡/IP，管理员启动时自动放行所选 TCP 端口，限定接口、本地 IP 和对应客户端子网；控制台“独立战术雷达”和启动窗口显示唯一访问链接。其他设备连接该网络后打开 `http://选中网卡IP:8765/radar`。`-LocalOnly` 仅监听 `127.0.0.1`；直接运行 EXE 时需同时传入 `--lan true --lan-ip IPv4 --lan-if-index 接口编号`。换网或开启热点后需重启服务。
移动 exe 时同时复制 `native/webui`，通过 `--web-root` 和 `--windivert-dll` 指定实际资源位置。

## 雷达历史回放（0.5.9）

点击雷达顶部“回放”，从列表选择已结束的采集记录并“载入回放”。列表读取当前服务输出目录（默认 `captures/webui`）中的 `web-*.jsonl`，不需要另录视频。手机可直接选择主机记录；正在写入的那条记录暂不可载入，其他历史记录可在实时采集期间回放。

下方进度条支持拖动、播放/暂停、0.25/0.5/1/2/4 倍速和返回实时。回放采用记录的虚拟时间，暂停不会因现实时间流逝而丢失人物。显示开关和物资筛选仍直接作用于当前雷达，包括暂停状态；回放期间停止当前页面的实时轮询，其他浏览器和采集服务不受影响。回到实时后重新接收当前战斗流。

C++ 从已保存的解析事件重建战斗流、人物、独立视角/生命/装备状态和物资，沿用当前 BattleTracker；每 50 ms 合并显示状态并用字段增量减少传输，绘制仍使用现有插值/平滑。回放不能补齐日志未保存或未解析出的字段，不重新获取密钥。后台转换不会把 bank、TCP 明文或 UDP 原始载荷返回浏览器。旧日志必须包含已确认战斗流及人物解析事件。单条日志最大 1 GiB、8 小时，转换后数据上限 128 MiB；截断 JSON 行会跳过并在页面报告数量。

## 扫描与选择设备

1. 页面读取网卡并优先选择实际网络连接。共享采集时切换为客户机所在的热点/私有网卡。
2. 首次打开自动扫描；“每 60 秒自动扫描”在页面可见且上一轮结束时再次扫描，也可手动开始/停止。
3. 先读取所选网卡的 Windows 邻居表，再以其 IPv4 为源，使用 12 个并发 worker 发出 ICMP Echo；每地址一次、250 ms 超时。
4. 显示 IPv4、MAC（若邻居表可得）、本机/网关角色、发现依据及 ICMP 往返时间。支持 IP/MAC 筛选，点击“选为客户机”填入采集表单。

只扫描所选网卡，不同时扫描所有虚拟网卡。最大完整范围为 /20（4094 个可用地址）；
更大网段只扫描本机所在的 /24，并在页面显示范围受限。/31 支持点对点，/32 不探测其他地址。
请求不能指定任意目标网段，后端要求网卡索引和源 IPv4 属于本机当前启用的接口。

“在线”表示收到 ICMP 回复或邻居状态为 reachable；历史 stale/permanent 等缓存标为“待确认”。
防火墙、AP 客户端隔离、休眠会影响发现；不响应不等于一定离线。
没有端口扫描、系统指纹或外部 MAC 厂商查询；无法可靠识别名称的设备显示“未识别设备”。

## 采集操作

- 先按 [共享网络说明](SHARED_NETWORK.md) 配置热点/ICS，确认客户机通过主机上网。
- 默认只复制 UDP，远端 UDP 端口为 0 表示采集该客户机全部 IPv4 UDP。
- 被动解密可选择输出目录 `banks` 下的 128 字节 bank；列表仅显示规范 SHA-256 文件名，不向页面发送密钥内容。
- 开启“TCP 接入（端口 65010）”即可，无需填写 TCP 端口或服务器 IP；采集启动后让客户机新建连接。仅接入到远端 65010 的连接并识别 TGCP mode 3，其他端口直接通过，同网段通信绕过。DH 公钥仅初始握手时替换，拿到 bank 后仍保持两侧密钥转换中继。
- “检查配置”验证网卡/IP、DLL 导出和过滤器，不打开驱动，不能替代实际连通性测试。
- “开始采集”生成唯一 JSONL 文件，页面显示 UDP 数、明文数、状态和连接/bank/错误事件。
- TCP 模式先由系统分配并绑定监听端口，再通过 Windows Firewall COM 创建仅限当前 exe、客户机 IP、主机私有 IP 和监听端口的临时入站规则，正常停止或异常退出时移除。
- “停止采集”协作取消并清理队列/中继；被接管的 TCP 连接会关闭，客户机需重连。
- 结束后可查看本次 bank 报告，多次会话累积分析仍使用原 `report` / `collect.py`。

默认输出 `captures/webui`；勾选保存 bank 才写入其 `banks` 子目录。
刷新网页恢复正在运行的配置和状态，不创建第二个采集。
解密后的包自动进入 C++ 人物解析器。“人物数据”仅展示当前战斗流最多 128 个槽位的最新名字、队伍、X/Y/Z、朝向、样本时间和质量；超过 2 秒未更新标为历史样本。未关联身份显示槽位编号。页面不逐条刷新人物日志，完整样本和验证结果保存在本次 JSONL 文件中，采集结束追加解析统计。

0.3.2 使用原版规则：控制通道 Welcome 中识别 `/Game/...` 后确认战斗流，在已确认流中自动选择最近收到明文的流。页面显示当前地图、地址/端口、epoch 以及“等待战斗流 / 战斗流活跃 / 战斗流空闲 / 采集已停止”。超过 15 秒无解密 UDP 明文（上下行均计入）时清空当前人物表；由采集循环独立计时，关闭页面或没有任何新包也会触发。明文恢复后重新显示。切流时按 flow/epoch 隔离人物，绑定重置和新 epoch 都需重新确认 Welcome。中途采集漏过 Welcome 时保留日志样本但不激活显示。

`/api/state` 的 `capture.battle` 返回状态、地图、flow、epoch、15 秒阈值、上次状态变化原因；`capture.players` 仅包含当前活跃流。`battle_welcome` 和 `battle_state` 写入采集 JSONL。空闲只表示传输静默，不声明游戏结算，也不控制 TCP 中继。

0.3.3 新增实时速率，统计窗口为最近 1 秒，页面每 0.5 秒读取后端结果：

| 显示 | 统计口径 |
| --- | --- |
| UDP 解密速率，包/秒 | 所选客户机全部流成功输出明文的下行 UDP 包；上行明文和解密失败不计入 |
| 坐标更新频率，Hz | 当前确认战斗流中输出坐标的源包数；同包包含多个人物时只计一次 |
| 坐标样本产出，条/秒 | 当前确认战斗流实际输出的位置样本数；每个人物分别计数 |
| 人物表更新速度 | 每槽位的样本 Hz 和距上次更新的时间；悬停显示相邻样本源包时间间隔 |

速率按后端收到事件的单调时间计算，不依赖浏览器轮询间隔。没有新数据时一秒窗口内的旧计数自动过期；切流、epoch 变化、空闲、重绑会清空当前坐标速率，停止或重新采集会清空所有速率。页面断开连接时速率显示 `—`。这些值表示本机处理到的数据节奏，不是游戏 FPS、服务器 Tick Rate 或网络往返延迟；合理性验证未通过的已解析样本仍计入样本产出，质量标记另列。

0.3.4 将“解析错误”和“部分解析提示”分开计数。人物质量栏会显示“部分解析：已读取坐标”；悬停显示未通过原因或解析停止原因。部分解析表示后续字段尚未支持，已读取的坐标仍须通过原有合理性检查，不代表整包解析完整。

0.3.6 起，预期的 `0x10` 停止不再产生警告事件，也不计入“部分解析提示”数量。人物样本的解析覆盖信息仍保留，其他警告/错误照常显示。旧版已经写入的日志不作修改。

0.4.0 增加「二维雷达」和本人上行数据；`/api/state` 的 `capture.self` 是当前流的自身验证结果，切流、idle 和停止时与人物列表同步清理。显示半径、方向/坐标规则及保存格式参见 [RADAR.md](RADAR.md)。

0.4.1 雷达独立请求 `/api/live`，响应后间隔 33 ms 再请求；动画按显示刷新节拍绘制，目标最高 60 FPS。接口仅含 `revision`、`serverTimeMs`、`running`、`battle`、`players`、`self`、`rates`，避免高频复制扫描和事件日志。人物行包含 `track`、`poseSequence`，用于限制插值状态。网络失败或 1.5 秒收不到响应时清屏；后台页面降低查询频率并暂停绘制。默认 120 ms 插值延后可通过「平滑移动」关闭。具体口径和最新日志结果见 [LOG_REVIEW_041.md](LOG_REVIEW_041.md)。

`capture.rates` 包含 `windowMs`、`udpDecryptPacketsPerSecond`、`coordinatePacketsPerSecond`、`coordinateSamplesPerSecond`、`selfSamplesPerSecond`、`lastDecryptAgeMs`、`lastCoordinateAgeMs`。本人上行速率独立统计，不混入下行坐标速率。各 `capture.players` 行附加 `updatesPerSecond`、`lastUpdateAgeMs`、`sourceIntervalMs`，未知时间为 `null`。速率为 WebUI 内存统计；原始包、样本和验证结果仍按原方式写入 JSONL。
WebUI 不自动开启 ICS、更改网关或处理 TLS。
强制杀进程/断电可能留下 `RadaerNativeShared-*` 临时防火墙规则；正常 Ctrl+C 会协作关闭。

## 接口与请求边界

`GET /api/bootstrap`、`/api/network`、`/api/state`、`/api/live`、`/api/banks` 返回服务状态。仅本机模式检查 loopback 来源；局域网模式只接受选中网卡的私有 IPv4 Host 及其对应子网来源，其他本机地址不监听。`bootstrap.lanUrls` 列出唯一访问地址，`lanIfIndex` 表示选中的接口。
扫描、预检、开始、停止和报告使用 `POST /api/...`，校验允许的 Host、同源 Origin、JSON 类型和服务随机 token，正文限制 16 KiB。局域网客户端与本机控制台拥有相同操作权限；token 用于防止跨站请求，不是登录密码。
不提供任意本机文件读取、不用 shell 拼接用户参数，不把设备/错误内容作为 HTML 插入页面。
`POST /api/server/stop` 可供本机集成正常退出。

## 验证范围（2026-10-18）

Windows Release 构建和 15 项 CTest 通过。WebUI 接口测试覆盖资源、请求边界、错误配置、邻居表发现、模拟采集启停和报告，以及非空人物和本人样本、当前战斗流 API、完全无包时的 15 秒超时清屏和停止状态。速率测试验证单包多人物去重、上下行区分、窗口过期、轮询不影响统计、切流/epoch/断档清零；HTTP 测试验证 22 个解密包、18 个坐标更新包、36 条下行坐标样本以及每槽位 18 Hz 的合成突发输入，并验证独立的 5 条本人上行速率、轻量接口内容及跨站请求拒绝。
扫描范围覆盖 /24、/20、大网段限制、/31、/32 和 loopback 拒绝。
采集生命周期测试使用模拟 DLL，真实 WinDivert 驱动未打开，没有更改当前 ICS/防火墙。
浏览器访问本机页面被权限策略拒绝，未完成浏览器视觉、页面点击和真实 ICMP 扫描验收。
实际热点/ICS 转发、游戏解密及人物准确性仍需实机验证。
