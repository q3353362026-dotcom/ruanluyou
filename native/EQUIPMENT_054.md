# 0.5.4 手持武器、头甲等级与血量环

雷达头像外围圆环表示当前 HP / 最大 HP，12 点方向为起点。0 HP 的进度为空，未知 HP 使用灰色虚线，队伍颜色仍用于方向箭头、编号和有血量部分。暂存位置使用独立外层虚线；倒地十字保留。列表头像也使用血量环，详情保留精确数值。

最大血量读取 `GPAttributeSetHealth.MaxHealth` 的 CurrentValue，实测包含 90、95、100 及 AI 的 350、450。尚未收到上限时仅绘制比例使用 100 作为参考，并在设置说明、详情中明确标记；不会生成假的 Health/MaxHealth 网络字段。未知 HP 不假装满血。

装备功能由 C++ 实现，不需要运行 Python：

- `SOLCharacterEquipComponent`：有界 RepLayout 数组增量，物品 ID 与原项目本地装备表映射头盔、护甲名称及等级，不用耐久度猜等级。无可靠 ID 或映射冲突显示未知。
- `WeaponReplicateComponent`：当前活动武器数组的 slot 0，通过 identity 与 ExtraData 的明确对应解析手持武器；支持 FastArray field 17 的重置、删除和更新。携带列表、首把装备武器不作为手持依据。
- 支持武器附件、皮肤及动态属性的有界读取，以正确消费数据边界；不把这些中间数据作为新显示字段。
- 子对象必须具有明确的 Character Outer GUID 关联；未知布局、截断、越界不提交该块，不更改移动解析连续性。
- 装备以 `equipment` 随人物/本人快照与独立 `player_state` 发布，具备时间和顺序；旧更新不能覆盖新状态，清空数组不会继承旧装备。网络流及 epoch 隔离沿用已有逻辑。

地图与人物列表提供独立的“人物名称”“干员名称”“手持武器”“头盔与护甲等级环”开关，默认开启，保存在本机浏览器。旧版合并开关的状态会迁移至对应的两个新开关。

头甲等级显示在头像内部：左弧为头盔、右弧为护甲，1–6 级依次为白、绿、蓝、紫、金、红色；未知或不支持的等级用灰色虚线，不冒充一级。内弧保持朝向固定，外层血量环仍按 HP 比例显示。地图与列表省去头甲等级文字，详情保留精确等级及武器信息。

## 验证

- 合成协议测试覆盖装备数组清空、切枪后 identity 未解析、空手、乱序拒绝、截断边界与独立状态事件，手持样例与原版 Python 解码器对照。
- 现有采集 `web-1792385995738-484d250f.jsonl`：892 个武器块、47 个 Character 与原版当前武器结果逐条一致；原始日志仅离线回放，无实际网络接管。
- 新旧回放坐标、位姿时间、采样数量及原有告警/错误数量一致。既有日志仍有 10 个错误、11 个警告，并非由本次装备接入产生。
- 本次完整 CTest 20 项通过；新增血量环语义检查及装备状态投影检查。

生成器：`tools/generate_equipment_schema.py`。本地原版物品表提供名称与等级；未知新物品保留 ID/未知提示，不按相似名字代替。
