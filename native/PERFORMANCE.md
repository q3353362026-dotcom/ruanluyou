# 0.3.5 解析性能验证

此文保留 0.3.5 的历史解析基准。0.4.1 已改变雷达刷新方式；最新日志中真实坐标频率、错误检查和绘制改动见 [LOG_REVIEW_041.md](LOG_REVIEW_041.md)。

2026-10-18，Windows x64 / MinGW UCRT64 C++20 / Release `-O3 -DNDEBUG`。比较 0.3.4 与 0.3.5，在本机固定日志快照上测量；不是实机网络吞吐量、服务器更新频率或端到端显示延迟测试。

输入为此前 SDK 分析使用的同一只读快照：89,380,820 字节、100,711 条事件，其中 21,422 个 UDP 明文包。SHA-256：`7a471bdd999aabb33e6d8075218946b215127fcecfa1be0661116bad281f0d69`。

## 修改

- 位读取由逐位循环改为按字节合并，保留边界检查，支持任意起始位和 0–64 位长度。
- 位切片、分片拼接按字节处理；对齐切片直接复制，尾部位仍正确遮蔽，拼接保留原 OR 语义。
- 人物样本与事件直接构造 JSON 对象，移动已有数据，避免 initializer_list 中间对象和整棵 JSON 树的重复复制；读取坐标/属性中间值使用引用。

## 内存解析基准

先加载并解析输入 JSONL；正式计时不含输入文件读取和 JSON 反序列化。每种模式预热一次、独立运行七次，取中位数。每轮重建解码器状态，验证计数和结果摘要一致。

| 模式（处理全部 21,422 包） | 0.3.4 | 0.3.5 | 耗时减少 |
|---|---:|---:|---:|
| UE 包/bunch 分帧 | 123.80 ms | 38.10 ms | 69.2% |
| 完整人物解析、生成事件 | 607.63 ms | 380.80 ms | 37.3% |
| 人物解析 + 合理性校验 | 733.72 ms | 516.95 ms | 29.5% |
| 人物解析 + 校验 + 事件 JSON 序列化 | 869.12 ms | 658.90 ms | 24.2% |

人物解析平均每包由 28.36 μs 降到 17.78 μs，折算该回放负载的吞吐由 35,255 包/秒升至 56,255 包/秒（约 1.60 倍）。这是批量离线处理能力，包含无人物更新包，不是单包延迟的百分位数。上表未包含 UDP 解密、磁盘写入、实际抓包或 WebUI 状态维护。

## 含文件读写的 CLI 回放

使用 `decode-players` 读取完整 89 MB 日志、重新做人物解析/校验/战斗状态维护、写出全部结果。新旧版本交替顺序运行，各预热一次、计时三次；输出写入新目录，进程返回后计时结束。

| 指标 | 0.3.4 | 0.3.5 |
|---|---:|---:|
| 中位耗时 | 2,845.60 ms | 2,549.02 ms |
| 耗时减少 | — | 10.4% |

此处包括输入 JSON 解码、操作系统文件缓存和缓冲输出，故整体收益小于纯解析收益。实时采集的 Journal 仍每事件 flush，本轮没有改变日志持久化策略，也未测量该路径的真实吞吐。

## 一致性与测试

13 项 CTest 全部通过。新增 381,995 项位流检查与慢速逐位参考比较，覆盖所有起始位、0–64 位读取、未对齐 64 位、空输入、截断不移动游标、切片尾位、任意对齐拼接和终止位。既有 358 组原 Python 差分向量与人物/网络模拟测试通过。

同一日志的以下七个文件在所有比较轮次中 SHA-256 完全一致：`players.jsonl`、`player-quality.jsonl`、`identities.jsonl`、`decoder-errors.jsonl`、`decoder-warnings.jsonl`、`battle-events.jsonl`、`summary.json`。因此时间、序号、坐标、关联、质量标记、错误和顺序均一致，不只是样本数量相等。

仍有 20,491 条坐标、83 条错误、276 条部分解析提示。性能优化不改变未知 `0x10` 对象的支持范围，也不降低可靠性门槛。

## 复现

在已配置的构建环境中：

```powershell
cmake --build native/build --target radaer-player-benchmark -j 4
native/build/radaer-player-benchmark.exe C:/captures/snapshot.jsonl decode 7
native/build/radaer-player-benchmark.exe C:/captures/snapshot.jsonl serialize 7
```

模式还支持 `packet` 和 `validate`。工具只读取日志，输出测量 JSON，不开启抓包。要比较修改前后，需分别保留对应构建的 benchmark 可执行文件，并使用相同输入和参数；避免同时运行多个基准进程。

本次原始计时、输出哈希及回放文件位于开发目录 `native/build/performance-20261018/`，不包含在运行包内。页面仍每 500 ms 刷新；优化解析不会增加服务端发送的坐标更新次数，也不能直接等同为页面刷新率提升。
