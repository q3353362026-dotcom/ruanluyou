# 独立雷达与扩展数据 · 0.5.0

版本说明：本文保留 0.5.0 的实现和验证记录。5 秒坐标超时隐藏问题已在 0.5.1 改为按独立生命状态及生命周期处理，当前规则见 [血量与人物保留规则](HEALTH_LIFECYCLE_051.md)，原因调查见 [人物坐标消失追踪](COORDINATE_LOSS_REVIEW_050.md)。

启动根目录 `start.cmd`，采集时使用 `start-admin.cmd`。控制台为 `http://127.0.0.1:8765`，独立雷达为 `http://127.0.0.1:8765/radar`（也支持末尾 `/`）。控制台提供「打开雷达」入口；两页共享同一 C++ 采集与解析服务，不会重复抓包。更改启动端口时，两页使用同一新端口。

## 视图

参考原版的全屏地图、浮动设置、人物列表和底部工具布局，采用深蓝灰面板与柔和队伍色。本人绿色、同队蓝色、其他队伍按 TeamID 分色，未知队伍灰色。人物用带方向箭头的圆表示，支持姓名、距离/高度差、轨迹、视角线、队伍过滤、搜索、排序、详情、跟随、缩放、全体居中和全屏。窄屏默认收起侧栏。

沿用原版 `map_catalog.json` 的地图标定与瓦片地址，提供零号大坝、长弓溪谷、航天基地、巴克什、潮汐监狱及 AZ3；需手动选择与对局一致的地图。Leaflet 脚本和样式本地提供，地图图片来自 `https://game.gtimg.cn`，断网可切换「坐标网格 · 离线」。尚未移植原版 3D、物资点及全部配置功能。

默认使用原版 120 ms 指数趋近，亦可选择延后 120 ms 的时间插值或原始坐标。速度辅助预测默认关闭，开启后仅在原版平滑模式、完整有效且新鲜的速度样本上使用，最多外推 80 ms。切流、身份变化、长间隔、大幅跳变时清理或跳过平滑。速度、朝向与位置都沿用各自采样时间，旧视角不会使坐标重新变成新鲜。

雷达绘制目标最高 120 FPS（实际受显示器刷新率和浏览器调度影响），`/api/live` 请求完成后间隔 20 ms 再请求，不堆积并发请求。控制台仍按 500 ms 刷新；后台雷达暂停绘制并降为约每秒查询。真实坐标 Hz 与画面 FPS 分开显示，视角更新不会增加坐标计数。本人显示仍以上行数据为准。

短时缺行、单次质量校验失败或接口请求失败时，地图、人物列表和选中详情保留最后一次有效坐标；超过 500 ms 没有新坐标或确认发生上述中断时，以淡色虚线标记「暂存」。暂存上限为原始坐标时间起 5 秒，轮询、重复坏样本和独立视角更新均不能续期。暂存期间不使用速度预测，收到新的有效坐标立即恢复更新。新人物占用同一槽位、切换 flow/epoch/会话、进入等待/空闲状态或明确停止采集时立即清理，避免把旧人物留到新对局。首次打开页面没有缓存时，不显示无有效历史的坏样本。

WebUI 在服务启动时读取静态资源。更新这些文件后，需要在合适时机停止并重新启动 WebUI，再重新打开雷达；仅刷新旧服务的页面不会加载本次修改。

## 数据扩展

以下为已经解出的字段，缺失或不能确认的字段保持缺失；不会根据相邻内存字段猜测血量、弹药或相机矩阵。单位沿用 UE 坐标厘米、速度厘米/秒，页面速度换算为米/秒。

| 数据 | 内容和来源 |
| --- | --- |
| `motion.velocity` | 下行 h21 完整移动项的 `pv` 向量，已与位置差分交叉核对 |
| `motion.bodyRotation` | 解出的原始身体旋转向量 |
| `motion.viewYaw/viewPitch` | `u160` 高/低 16 位解包为视角度数，带独立 `viewAtMs` |
| `motion.timeSeconds` | 协议游戏时间，附 `timeAtMs`；不硬编码为墙钟时间 |
| `attributes` | 已有 PlayerState 属性投影：英雄/阵营类型、机器人标记、存活/死亡/濒死、死亡盒、救援时间、游戏状态；只提供实际存在的值 |
| `player_motion` | 只有视角等运动更新、没有新坐标时的独立事件；合并到相同 flow/epoch/track，保留坐标时间与序号 |
| `self_server_sample` | 下行完整帧中的本人候选位置/速度/视角，独立轨迹与验证；保留 `identitySource: embedded_self_candidate`，不会自动替代上行本人 |

完整帧之外的 `known_prefix` 样本不采用未确认的运动字段。遇到 `mask 0x10` 继续按既有约定在它之前停止，保留此前坐标，不重新产生此类警告。

上行字段在 0.5.0 修正语义：`velocity` 为 SDK 的 `ClientVelocity`，`acceleration` 为 `InAccel`（输入加速度，并非由坐标差分测量的物理加速度），并增加 `vectorSchema: FGPMoveParams_v2`。旧版这两个顶层字段名称对调；使用旧日志的消费者应根据版本/schema 区分。上行 lite 没有真实速度时为 null，不把输入加速度当速度。低层参考解码结构不变。

`/api/live` 的人物行和 `self` 传递 `motion`、`attributes`；新增 `serverSelf` 保存独立的下行本人候选验证结果。详情中只有两侧本人数据均有效、新鲜且身份相符时才显示上下行位置差。该数值是两次采样位置差，含采样时间偏差，不代表网络 RTT 或绝对定位误差。

实时 JSONL 增加 `player_motion`、`self_server_sample`、`self_server_validation`。离线 `decode-players` 增加 `motion-updates.jsonl`、`self-server.jsonl`、`self-server-quality.jsonl`；summary 增加 `motionUpdates`、`serverSelfSamples`。原有保存方式和坐标质量规则保持不变。

## 验证（2026-10-19）

Release 构建成功，18 项 CTest 全部通过。覆盖新字段解码、视角增量、本人上下行隔离、过期/乱序、切流/重置、地图坐标、方向、原版平滑、插值、预测边界、帧率上限、独立静态路由与 HTTP 路径边界；既有原版差分测试继续通过。

120 FPS 与暂存更新另通过 `tactical_radar_view` 回归：覆盖 30/60/90/120/144/165/240/360 Hz 调度输入、5 秒保留/过期、连续坏样本不续期、槽位复用/切流清理，以及真实页面脚本在模拟接口失败、恢复、停止过程中的列表与选中详情状态。没有将调度测试当作实机达到 120 FPS 的证据；本次更新不涉及 C++ 解码和校验逻辑。

同一真实旧日志的 16,036 条上下行校验事件进行显示模型复核：121 条未通过样本中，88 次可以沿用同一人物的有效缓存，其余 33 次没有符合保留条件的历史位置，继续隐藏。该检查固定使用记录中的单一战斗流；结果保存为 `native/build/radar-retention-check.json`，不是新的在线采集测量。
