# 血量与人物保留规则 · 0.5.1

人物生命状态、血量、视角和坐标分别更新。存活人物长时间静止时，不再因最后一条坐标超过 5 秒而消失。坐标时间与坐标 Hz 不会被血量或视角事件刷新。

## 解析与显示

C++ 移植原版 `property_health.decode_health_block` 和 `HealthBatchTracker` 的健康批次格式：有界容器、稠密/稀疏存在集、每项位长度、严格递增字段句柄。整个块解码成功后才提交；未知句柄、非有限浮点数、截断或多余位拒绝该块，不猜测后续布局。原有 mask 0x10 的静默停止行为保留。

`Object` GUID 通过已导出的 `AttributeCenter` / `GPAttributeSetHealth` 的 Outer 关联 Character。健康容器索引不是 Movement 的 slot，不能直接关联人物。支持导出延迟到达、对象/容器索引复用和独立字段增量。

支持 `Health`、`ShieldHealth`、`ArmorShieldHealth`、`ArmorHealth`、`HelmetArmorHealth`、`IsAlive`。生命状态也接收完整、已验证 PlayerState 的 `CurrentCharacterLiveStatus`。这些字段均保持独立的时间和来源；同一网络包中的逻辑 bunch 保持处理顺序，避免死亡/复活被合并丢失。同一观测次序冲突时健康批次优先于 PlayerState。

生命枚举为 1=存活、2=死亡、3=倒地。倒地的 `alive=true, downed=true`。血量为 0、通道关闭、移动静默、未知枚举均不直接证明死亡。未收到 HP 显示“—”，没有生命证据显示“状态未知”；不假定当前血量或最大血量是 100。此版接入的是健康批次及 PlayerState 生命状态，未另行移植 GPAttributeSetHealth 子对象的完整属性表。

雷达名称下方及列表显示状态和 HP，倒地显示黄色十字；详情增加存活/倒地布尔状态、血量更新时间及已收到的护盾、护甲、头盔数值。视角即使在坐标静止超过 2 秒后也继续更新；旧角度作为最后已知朝向保留。

## 保留与清理

| 事件 | 当前行为 |
| --- | --- |
| 已确认存活/倒地，坐标不再变化 | 当前战斗流内保留最后有效位置，标注暂存，禁止继续速度外推 |
| Dormancy / close reason 1 | 保留人物和身份关联 |
| Relevancy / close reason 3 | 保留，标注“超出同步范围”；不是死亡或确定离场 |
| 明确生命状态为死亡 | 立即从活动雷达隐藏；缓存保留用于后续明确复活，恢复时仍显示原坐标时间 |
| Destroyed / LevelUnloaded / TearOff（0/2/4） | 清理显示与旧人物关联；通道关闭本身不改写生命枚举 |
| 槽位/人物身份复用 | 清理旧人物缓存；不将旧血量、坐标交给新人物 |
| 新对局/切流/epoch 改变/停止/15 秒战斗流静默 | 按战斗流状态清空视图 |
| 生命未知 | 不自动判断死亡，最后坐标最多保留 300 秒 |
| 页面取不到服务数据，或接口持续缺失人物行 | 允许 5 秒短暂保留；此计时从最近成功响应/首次缺行开始，与坐标年龄分离 |

旧实现把 reason 3 与销毁混为一谈也会造成短暂隐藏。原版 `LiveView._actor_removed` 的实际代码只把 0/2/4 作为最终通道移除条件，虽然较早的 `_handle_char_close` 注释仍列出了 3；本版遵循最终判定。

实时采集日志新增 `player_state` 事件；`decode-players` 另存 `player-state.jsonl`。位姿行包含 `vitals.health`、`vitals.life` 与 `lifecycle`；HP/生命各自记录 `timestampMs` 与流内逻辑处理顺序 `sourceOrder`。重放从原始明文重新计算，不重复消费保存的状态事件。
