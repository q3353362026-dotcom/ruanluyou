# 简易二维雷达 · 0.4.1

本文保留 0.4.1 的历史行为与验证记录。当前 0.5.0 已改为独立 `/radar` 页面，地图、配色、平滑方式和扩展字段见 [RADAR_050.md](RADAR_050.md)。

运行包解压后用 `start-admin.cmd` 启动，在 WebUI 的「二维雷达」查看当前战斗流。已有正在运行的旧版本需在方便时自行停止并启动新版；构建和验证过程不会替换其进程。

人物以圆形和箭头表示，箭头随 yaw 旋转。金色为本人，绿色为同队，珊瑚色为其他队伍，灰蓝色为未知队伍。匹配 TeamID，双方 Camp 都已知时还要求 Camp 一致；缺失身份或队伍不判为敌方。本人同时出现在下行槽位时，按 Character GUID 去重。

支持 50 m–2.5 km 显示半径、跟随本人、全体居中、名称开关，悬停查看坐标和队伍。坐标单位为厘米，显示范围换算为米。固定 +X 向右、+Y 向上，yaw=0 箭头向右，yaw=90 向上。暂无地图贴图/地图方向标定、地形、楼层和 3D 模型；底图是二维坐标网格。

雷达使用独立 `requestAnimationFrame` 动画循环，目标最高 60 FPS，实际 FPS 取决于显示器和浏览器负载并在页面显示。轻量 `/api/live` 请求完成后间隔 33 ms 发起下一次，不并发堆积请求；日志、设备和人物表仍每 500 ms 刷新。后台标签页暂停绘制并降低查询频率。

默认开启「平滑移动」：延后 120 ms，在已收到的相邻坐标间插值，朝向按最短角度旋转。可关闭以直接显示最新采样。不会向未来外推；超过 500 ms 的间隔、超过 25 m 的单次位移、身份或战斗流变化都不跨越插值。SVG 网格和人物节点复用，避免每帧重建整张图。页面的真实数据 Hz 与绘制 FPS 分开显示；绘制 60 帧并不表示服务端每秒发送 60 个新坐标。

不显示验证失败或超过 2 秒未更新的坐标，预热中的标记以虚线/半透明显示。本人坐标暂缺时按可见人物居中，并明确标注等待本人数据。无 Welcome、切换流/epoch、采集断档、停止、15 秒明文静默和服务连接中断均隔离或清除展示。未解析朝向时仅显示圆形，不假定朝向为零。

## 本人数据与保存

上行 `udp_plaintext` 已由采集层剥离 8 字节业务前缀；解码层经 UE packet/bunch 和独立上行分片重组，仅对 ch3 尝试原版 `parse_fgp` 对应结构。固定 bit 53 起读，校验时间、向量范围和精确尾部边界，支持 full/lite。其他 ch3 消息正常忽略，不生成大量解析错误。

同一包多个移动消息保留最后一个位姿，与原版 LiveView 一致。同一采集毫秒内的不同包，可使用单调前进的游戏内时间计算间隔；倒退时间不因此放行。自身身份由下行 Character ch3 → PlayerState 关联，不使用最近距离猜测。只得到位置/速度/yaw/pitch，并非相机矩阵。

实时采集在原 JSONL 中保存 `self_sample`、`self_validation`。`decode-players` 额外生成 `self.jsonl`、`self-quality.jsonl`，summary 中增加 `selfSamples`。原有下行人物文件保留；顶部坐标速率仍统计下行，避免将自身上行混入远端槽位速率。

## 队伍修复

- 原版 Character NewActor 变换后再跳过 8 位才能读首个内容块。原 C++ 缺少该偏移，队伍属性虽已读取，人物关联却失败。
- 完整 Character 属性块可在后续子对象尾部不完整时保留，尾部异常仍记录提示，不把截断块当完整字段。
- Character.PlayerState 明确 GUID 优先；缺失时仅允许唯一 PlayerState 通过共同 Controller Owner 关联，不把 Owner GUID 直接当成 PlayerState。
- 更新的明确 MoveHandle 分配接管复用槽位；解除后不恢复旧主人；同一来源时刻冲突保持未知。绑定重置和通道关闭清除旧身份。
